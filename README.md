# overlay-autostart — автозапуск overlay-only init-скриптов

Общий фикс для наших кастомных сервисов на Капсуле (прокси, dropbear, будущие).
Ставится один раз; после него любой `/etc/init.d/S??*`, которого нет в прошивке,
запускается при загрузке.

## Проблема

`/etc/init.d/rcS` раскрывает список `S??*` **один раз**, до того как
`S23overlayfs.sh` смонтирует overlay (pivot: исходный корень-прошивка уходит в
`/rom`). Скрипты, которые лежат только в overlay (`/data/overlay/upper`), в этот
список не попадают и при загрузке не стартуют. Поэтому `S50dropbear` и
`S96capsula-proxy` без этого фикса оживают только при ручном запуске.

Других точек входа нет: в `/etc/inittab` единственный `sysinit` — `rcS`, нет
`rc.local`, ни один `/rom`-скрипт не подхватывает внешний каталог-хук.

## Решение

Положить в overlay `S96stereoctl.sh` поверх штатного. Имя есть в `/rom`, поэтому
`rcS` его видит и исполняет нашу копию (для `*.sh` — `. $i` в подоболочке). Она:

1. запускает все overlay-only `S??*` (которых нет в `/rom/etc/init.d`), так же как `rcS`;
2. `exec`'ает настоящий `/rom/etc/init.d/S96stereoctl.sh` с теми же аргументами.

`exec` внутри форкнутой подоболочки `rcS` заменяет только её. Тело системного
stereoctl **берётся из `/rom`**, а не копируется к нам, поэтому OTA-обновление его
не затирает — это главное отличие от простого «скопировать скрипт целиком».

Позиция запуска — S96 (имя занятого скрипта), перед `S97voice-agent.sh`: прокси
успевает подняться до агента. Все overlay-only скрипты стартуют здесь же, в
лексикографическом порядке имён, независимо от своего номера.

## Установка

```sh
./install.sh                 # 10.0.0.227:5555
./install.sh 10.0.0.227:5555
```

Проверка: `adb reboot`, затем `ps` — должны подняться `dropbear`, `capsula-proxy`,
`stereoctl`, `voice-agent`. Проверено на устройстве 2026-11-12.

## Добавить новый сервис

Положить его `S??<name>` в `/etc/init.d` (например `adb push … /etc/init.d/S80foo`)
с интерфейсом `start`. Больше ничего — фикс подхватит его при следующей загрузке.

## Ограничения

- Шим занимает имя `S96stereoctl.sh`. Если OTA переименует/удалит этот скрипт в
  прошивке, шим станет overlay-only и перестанет запускаться (автостарт тихо
  отключится, ничего не ломая). Тогда выбрать другой штатный скрипт: переименовать
  шим и поправить `SHADOW` внутри него и `HOST` в `install.sh`.
- Все overlay-only скрипты стартуют в позиции S96. Если понадобится что-то строго
  раньше — нужен отдельный шим на более ранний штатный скрипт.
- Factory-reset (`S22factory-reset.sh`) стирает `/data` → фикс пропадёт вместе со
  всем джейлбрейком, переустановить.
- Откат: `adb shell rm /data/overlay/upper/etc/init.d/S96stereoctl.sh`.
